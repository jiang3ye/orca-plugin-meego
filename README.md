# Meego for Orca

在 Orca 侧栏连接飞书项目，浏览和维护工作项，关联开发工作区，再把工作项交给 Agent。个人连接使用飞书项目官方 OAuth，无需手动填写用户 ID、空间 ID 或插件密钥。

这是独立社区集成，非 Orca、飞书项目或 Meegle 官方产品。

**实验性项目：当前需要配套的自定义 Orca 宿主。公开版 Orca 暂不具备本项目依赖的全部平台 API。**

## 兼容性

已核查的公开 Orca **v1.4.257** 仍缺少本项目依赖的扩展，包括原生集成设置页、插件设置导航、可验证的工作区标识和按主机发现 Agent；其[严格面板 schema](https://github.com/stablyai/orca/blob/v1.4.257/src/shared/plugins/contributions/plugin-panel-contribution.ts)会拒绝当前使用的 `location` 字段。不能仅依据版本号安装使用。

配套宿主已有本地安装和分段验收记录。日常 CI 从 [`.github/orca-sdk.json`](.github/orca-sdk.json) 固定的 `jiang3ye/orca` 源码完整提交构建真实 Orca CLI，并校验生成声明与运行时资源一致。宿主改动已提交[上游草稿 PR #41598](https://github.com/stablyai/orca/pull/41598)，尚未完成官方公开宿主发布；manifest 中的宿主版本下限是平台语法门槛，不是公开版兼容承诺。

开始前需准备包含配套改动的宿主和与其匹配的 CLI。开发与发布流程见[开发指南](docs/development.md)和[发布指南](docs/releasing.md)。

## 快速开始

安装、禁用、卸载、移除开发挂载，以及断开或移除飞书连接的区别，见[安装与生命周期](docs/lifecycle.md)。

1. 在配套宿主加载插件，打开「设置 → 集成 → 飞书项目（Meego）」，点击「连接飞书项目」，在浏览器完成授权。侧栏「集成设置」可直达此页。
2. 返回 Orca，按名称选择可访问的空间。插件会保留该账号选择的空间。
3. 按类型浏览工作项，搜索标题或完整编号，也可以粘贴工作项详情链接。
4. 打开详情，按当前连接提供的能力查看评论、编辑字段或操作流程节点。开发时可关联当前工作区，或选择来源 Git 工作区，新建并关联开发工作区。
5. 点击「交给 Agent」，选择已有终端或本次要启动的 Agent。新会话选项来自目标工作区实际主机上已安装且启用的目录，无需设置插件全局默认值。

已有 Agent 终端接收待核对的单行草稿，需要在终端提交。新会话通过宿主启动和投递；请求成功后仍应在终端确认实际送达。没有现成 Agent 的命令入口会引导回面板选择，不会使用隐藏默认值启动。

创建工作区需要宿主支持并批准 `workspace:create` 权限；显式打开工作区使用 `workspace:write`。新建操作先在后台创建并关联固定工作区 ID，再由用户显式打开；不会自动启动 Agent。

## 当前能力

| 操作 | 支持范围 |
| --- | --- |
| 浏览与查找 | 空间、类型、标题或编号搜索、分页、跨空间详情链接，完整保留正数 64 位编号 |
| 视图 | 列表、表格、按真实状态分组；分组基于已加载数据，不支持拖拽改变状态 |
| 筛选与排序 | 从空间类型配置读取状态选项；按状态筛选；对已加载数据按更新时间、标题或编号排序 |
| 新建与评论 | 按模板及必填项创建工作项；分页查看和发布评论；复杂字段可转网页处理 |
| 字段与状态 | 个人连接按实际元数据提供标题、描述、优先级、角色成员和可用状态流转；系统计算的当前负责人只读 |
| 节点流程 | 查看节点、状态和负责人；条件允许时确认完成、带原因回退或修改独立节点负责人；角色继承分配转网页处理 |
| 工作区 | 关联当前工作区，或核对来源仓库、主机和分支后新建关联工作区；创建记录持久保存 |
| Agent | 预览工作项后写入所选终端草稿，或显式选择新 Agent；按实际主机目录校验 |

状态筛选暂不包含终止项。个人连接的「分配给我」匹配当前负责人；企业连接的「与我相关」范围更广，暂不支持与状态筛选组合。本地排序不会改变服务端分页顺序，也不代表整个空间的全量排序。

创建表单支持可识别的文本、数字、布尔值、日期和单选字段。个人连接还支持业务线和使用当前账号填写人员字段；其他成员、附件等未支持字段可在网页完成。编辑角色成员和独立节点负责人时，可搜索服务端确认的成员。角色必须显式选择，只提交该角色的成员增删，保留其他角色；角色变化可能更新系统计算的当前负责人。

当前只实现飞书项目 / Meegle 连接。Jira 和 Linear 没有可用适配器；工作项、工作区和 Agent 的对应关系见[架构说明](docs/architecture.md)。

## 连接方式

默认个人连接地址为 `https://project.feishu.cn`。国际版可在集成页「高级设置」将 API 地址改为 `https://project.larksuite.com` 后授权。OAuth、令牌刷新和业务请求由 worker 处理，凭据使用 Orca 本机加密存储。授权未过期且 worker 仍在运行时，重新打开面板会继续等待原有授权。

企业 OpenAPI 连接仍可使用。在[飞书项目开发者后台](https://project.feishu.cn/home/developers)创建并安装插件、完成权限和数据授权后，在「设置 → 集成 → 飞书项目（Meego）→ 高级设置」填写 Project Key、User Key，再在同页「高级连接」保存 Plugin ID、Plugin Secret 并测试。私有部署需使用 HTTPS；工作项链接模板支持 `{project_key}`、`{work_item_type_key}`、`{work_item_id}`。密钥与保存时的 API 地址绑定。

企业连接保留浏览、状态筛选、创建和评论适配；字段编辑和节点操作需要个人 MCP 连接。国际版与企业连接尚未完成实机业务验收。

## 结果待核对时

写请求超时或无法确认结果时，不会自动重复提交。创建和评论保留草稿；字段、状态和节点操作提供只读回读及网页核对入口。核对后可采用最新结果，或明确确认尚未执行，再重新准备操作。这些草稿及待核对状态保存在当前面板会话中。

工作区创建另有持久记录：创建前落盘，收到回执后先保存，再关联。结果不确定时，核对并选择已创建的工作区恢复关联；原请求仍在执行时不能重新计划。已创建但关联失败时只重试关联。浏览空间和聚焦工作区的变化不会替换记录中的目标。

## 验证范围

此前本机安装的配套自定义宿主已确认可用，加密登录状态保留；原生集成目录、插件自身的设置导航与连接面板通过核对。当前工作区解析为稳定 ID，Agent 目录返回四个已安装选项，已有测试工作项可只读访问，原有 PTY 会话及 incarnation 已重新挂接。

此前两条获授权的测试记录覆盖创建、评论及回读，以及字段、角色、状态和节点操作。隔离配套宿主也验证过工作区创建、关联、显式打开和重复面板请求不重复创建，并由真实 Codex CLI 收到提示、返回验收回复。这些是分段证据；更新后仍需重新完成新 Agent 的实际交接验收。

隔离环境已验证正式 Git 安装的审批、启停、升级与实际回滚、卸载和重新安装，以及开发目录卸载。连接移除覆盖失败重试与重启后的防回退；这些验收没有清理真实账号。

离线验证包括 202 项行为测试、11 个检查场景，以及 20 张设置页和 36 张核心界面原生 fixture 截图。完整可视 GUI 回归尚未按指定的 Electron 技能执行，因为当前环境缺少该技能。组件截图和分段 RPC 验证不能替代完整端到端验收。

## 开发与贡献

准备 Node.js 24 或更高版本，并使用与配套宿主匹配的 CLI：

```sh
npm ci
npm run check
orca plugin inspect . --json
```

`check` 会生成官方 SDK 类型，依次运行 manifest 校验、严格类型检查、离线测试、面板场景和源码清单检查。CLI 由兼容的 Orca 构建提供，不要安装同名 npm 包。测试与检查场景使用合成数据和离线 mock，不需要真实账号。

每次 push 和 pull request 的 CI 配置同时包含三系统源码检查与 macOS 15 ARM64 的完整 SDK 检查。默认流程检出固定宿主源码提交，用 canonical generation 的 `--check` 校验 SDK 声明与运行时，运行宿主官方 CLI 构建，再确认 `out/package.json.commit` 与固定提交完全一致；不下载私有全量宿主 ZIP，也不使用手写 SDK 替代。

插件 `v*` 标签及手动选择公开宿主版本的检查另有门槛：必须使用已发布、已验证包含所需 API 的官方 Orca release，不能用配套分支的源码构建代替。当前尚无符合条件的已验证公开版本。每次云端结果见仓库 [Actions](https://github.com/jiang3ye/orca-plugin-meego/actions)，以对应提交和运行的完整 SDK job 日志为依据；前述 202 项测试和 11 个场景是本地验证基线。详见[发布指南](docs/releasing.md#github-检查)。
