# Meego development

## Required host

This is an independent community integration, not an official Orca or Feishu Project / Meegle product. The checked public Orca v1.4.257 does not include all required APIs; its [strict panel schema](https://github.com/stablyai/orca/blob/v1.4.257/src/shared/plugins/contributions/plugin-panel-contribution.ts) rejects the `location` field used here. A numerically compatible version is insufficient.

Default CI builds the real Orca CLI from the exact `jiang3ye/orca` source commit recorded in [`.github/orca-sdk.json`](../.github/orca-sdk.json). Its `repository` and full `commit` are the source of truth; do not duplicate a moving branch or a short hash in setup instructions. Generated declarations and runtime resources are checked together before building. The manifest engine floor describes platform grammar, not support in public Orca releases.

The required platform surface includes canonical workspace IDs, scoped `agents.available`, plugin-scoped `settings.open`, settings-only component panels, background workspace creation and readiness-aware Agent delivery. See [architecture](architecture.md) for their boundaries and [releasing](releasing.md) for compatibility checks before packaging.

## Layout and ownership

| Layer | Modules | Responsibility |
| --- | --- | --- |
| Worker entry | `src/worker.ts` | Connection lifecycle, read queries, create/comment handlers and registration |
| Workspace actions | `src/worker-workspace-actions.ts`, `src/meego/workspace-inventory.ts`, `src/meego/workspace.ts` | Explicit inventory target selection, canonical identity, associations, host Agent discovery and handoff |
| Durable creation | `src/meego/workspace-create.ts` | Per-item journal, no-replay creation and uncertain-result recovery |
| Item mutations | `src/worker-item-edits.ts`, `src/meego/work-item-edit*.ts`, `src/meego/work-item-nodes*.ts` | Account/source/version checks, metadata, roles, states and nodes |
| Connection | `src/meego/oauth.ts`, `src/meego/connection.ts`, clients | OAuth, encrypted credentials, region/account scope and provider adaptation |
| Sidebar | `src/panel.tsx`, `src/panel-*.tsx` | Browsing, editing, drafts and action-local choices |
| Integration settings | `src/settings.tsx`, `src/panel-connection.tsx` | Authorization, account, space and enterprise connection management |
| Shared contract | `src/protocol.ts` | Typed panel/worker requests and events |

Keep new behavior in its owning layer. Extract responsibilities when needed; avoid adding provider-specific conditions to the host or creating generic frameworks before another provider exists.

## SDK and verification

Use Node.js 24 or later and the matching companion CLI. Fresh clones install the pinned development tools and run the complete check:

```sh
npm ci
npm run check
orca plugin inspect . --json
```

`check` runs SDK generation, manifest validation, strict TypeScript, offline tests, panel scenarios and the source allowlist in order. Individual scripts include `sdk`, `typecheck`, `test`, `check:panels` and `check:source`. Orca supplies the CLI; the unrelated npm package named `orca` is not a dependency.

`tsconfig.json` extends `.orca/types/tsconfig.json`. This directory is generated by `npm run sdk` and ignored: do not edit it or restore hand-written Orca SDK mirrors. `types/node-runtime.d.ts` supplies only the missing Node primitives and assertion declaration. Keep the request/event augmentation in module `orca`; the official `orca/host` and worker types share that contract.

Tests fake HTTP and host boundaries and perform no live Feishu writes. Fixtures must use synthetic accounts, spaces, IDs, names and URLs. Retain response shapes, pagination, exact payload assertions and int64 boundary cases when sanitizing captured examples.

Add a behavior regression at the layer that owns the change. Prefer hardcoded expected payloads for identity, account/source boundaries and mutation outcomes. Avoid tests for colors, copy, private state or helper call counts. Settings tests must remain connection-only and must not query work items or workspaces.

The locally verified baseline is 217 passing behavior tests and 11 check scenarios. Presentation evidence contains 20 settings PNGs, 36 core UI PNGs and 20 workspace-flow PNGs. The separate isolated macOS Electron/CDP journey verifies the actual Meego components and worker through native workspace creation and Agent terminal display; screenshots alone do not supply that evidence. Its provider HTTP and model TUI are synthetic, with real host APIs, storage, workspace files and PTY. A current real cloud-model response, non-macOS and remote live flows remain separate acceptance scopes.

The Electron skill used for this run was recovered from [its upstream public history](https://github.com/stablyai/orca/blob/3a138a2f07f642390642db736a733580c50e9be3/.agents/skills/electron/SKILL.md). Follow the current host tests/AGENTS.md and tests/e2e/AGENTS.md background, profile-isolation and CDP rules over historical launch examples.

## CI SDK and release checks

Every push and pull request is configured to run source inventory checks on Linux, macOS and Windows, plus the complete `npm run check` on a macOS 15 Intel runner. The SDK job generates types, validates the manifest, typechecks, runs the offline behavior tests and all panel scenarios, and checks the source inventory. Source-only success cannot stand in for this job. Public-release SDK verification separately runs on ARM64; the default source build uses Intel to avoid the ARM64 capacity queue.

Default CI checks out the pinned host source and builds its official CLI. It does not download a private full desktop ZIP. In that host checkout, the canonical checks and build are:

```sh
pnpm install --frozen-lockfile
pnpm generate:plugin-declarative-typings --check
pnpm generate:plugin-declarative-runtime --check
pnpm build:cli
```

Before using the result, verify that `out/package.json.commit` exactly equals the pin's full `commit`. Use that built CLI for the plugin's complete `npm run check`. An inaccessible commit, stale generated output or identity mismatch must fail; it must not be replaced with a version-nearby CLI, a hand-written SDK or source-only checks.

Generated authoring declarations and runtime resources must come from the same checked source. Fix drift through the companion host's canonical generators and commit their outputs before updating the pin; do not mask it with plugin-local declarations or mocks that widen the real API.

Plugin `v*` tags and a manual public-release override require a compatible, published official Orca release. That gate is separate from the default source-built SDK and cannot be satisfied by a companion-fork build. There is currently no verified public release satisfying it. See the [release guide](releasing.md#github-检查) for the publication boundary.

These statements describe the workflow configuration. Cloud results are recorded in repository [Actions](https://github.com/jiang3ye/orca-plugin-meego/actions); cite the complete SDK job logs for the corresponding commit and run when reporting a successful cloud check. The recorded 217 tests and 11 scenarios above remain the local verification baseline.

## Local development

Use the companion CLI's documented development loader and watcher for source iteration. Orca compiles TypeScript/JSX when loading the plugin; editing worker dependencies can restart the worker and discard in-memory state. Coordinate edits before any separately authorized live acceptance window.

The sidebar and Settings frames share a worker and encrypted credential store, but each frame owns its atoms, subscriptions and request lifetime. Dispose authorization polling on close and discard late results after target or account changes.

Agent selection belongs to the handoff action. New sessions require an explicit ID from the target host's installed and enabled catalog, revalidated before launch. Existing terminals receive unsubmitted drafts. Retain the host terminal receipt and expose a separate open action; opening revalidates exact workspace/terminal membership and never resends the prompt. A command with no existing Agent directs the user to the panel; legacy defaults do not silently launch a session.

## Acceptance and local records

Installed-host checks have confirmed persistent encrypted login, native integration navigation, connection rendering, stable workspace identity, the target host’s installed and enabled Agent catalog, read-only access to an existing test item, and original PTY/incarnation reattachment. Earlier authorized business checks and isolated Agent delivery are segmented evidence; the new isolated rendered journey uses a synthetic HTTP provider and model TUI while exercising the real native workspace and PTY. It does not establish a current live model response.

Live business writes require an explicitly bounded scope and a durable record before submission. Ordinary tests and contributor checks must not use a live account. Keep rollback information and acceptance logs local; do not publish account identifiers, tenant labels, real item links or terminal identities.

Generated types, private acceptance records and installation metadata belong in ignored `.orca/`; screenshots belong in ignored `artifacts/`. Never commit profiles, encrypted stores, credentials or raw customer captures. Do not clear a profile, stop unrelated terminal daemons or bypass signing checks to make acceptance pass.

For the first public release, prepare a sanitized source snapshot and review its contents before creating public history. Deleting a private file from the current tree does not remove it from earlier commits. Follow the [release guide](releasing.md); do not push local development history as the initial public repository.
